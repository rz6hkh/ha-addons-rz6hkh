# Port steer

Перенаправляет TCP-порт **только для выбранных клиентов сети** в другой аддон.
Остальные клиенты по-прежнему попадают в то, что держит этот порт на хосте.

Пример: стиральная машина LG должна подключаться на 8883 к аддону rethink, а
конвекторы на том же 8883 — к брокеру MQTT. Правило «с IP машины, порт 8883 →
rethink» трогает только её соединения.

## Как устроено

- Работает в сети хоста с правом `NET_ADMIN`.
- На каждое правило ставит два правила `iptables` (движок nft, как у Docker):
  `DNAT` в `nat/PREROUTING` (с адреса клиента на локальный порт → в контейнер
  аддона) и `ACCEPT` в `DOCKER-USER` (пропустить именно этот поток через
  цепочку `FORWARD`, у которой по умолчанию `DROP`).
- Адрес целевого аддона берёт у Supervisor на каждом проходе: перезапустили
  аддон, сменился его адрес — правило переставится само.
- Все правила помечены комментарием `port_steer:<имя>` и снимаются при
  остановке. Остановили аддон или упал целевой — правило пропадает, клиент
  остаётся без перенаправления; остальных это не касается.
- Порт у целевого аддона на хост **публиковать не нужно**: трафик идёт прямо
  на внутренний адрес контейнера.

## Настройка

```yaml
interval: 30
rules:
  - name: lg_mqtts
    source: 192.168.50.70      # IP клиента (или подсеть /NN)
    port: 8883                 # порт, на который стучится клиент
    addon: xxxxxxxx_rethink    # slug целевого аддона
    target_port: 8883          # порт внутри целевого аддона
```

Клиенту нужен постоянный адрес (резервирование DHCP на роутере).

Проверить, что стоит на хосте (из терминала с правами root):

    iptables -t nat -S PREROUTING | grep port_steer
    iptables -S DOCKER-USER | grep port_steer
